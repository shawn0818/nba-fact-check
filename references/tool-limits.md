# 检索工具：能到哪、到不了哪

以下是 2026-10-17 对 DeepSeek Search / Fetch 的实测结论。别的搜索工具的覆盖面不同；有更好的工具就用更好的，但这些"到不了"的结论值得先知道，免得把"工具够不着"误判成"不存在"。

## DeepSeek Search

`POST https://api.deepseek.com/v1/tools/search`，命令行封装见 `scripts/search.py`。

**查询语法**（写在 query 里，query 最长 128 字符）：

| 写法 | 作用 |
|---|---|
| `site:bbs.hupu.com` | 限定站点，多个用 `OR` 连接 |
| `-site:xxx.com` | 排除站点 |
| `"精确短语"` | 精确匹配 |
| `-关键词` | 排除关键词 |
| `lang:zh,en` | 限定语言 |
| `after:2026-10-01` / `before:2026-10-15` | 时间范围 |

**返回字段**：`title`、`url`、`date`、`site_name`、`summary`、`authority`（0–4）、`rerank_score`（0–3），加 `need_content` 时还有正文 `content`。

**实测特点**：

- **中文体育站覆盖好、收录快。** 虎扑、直播吧、新浪、知乎的稿件当天就能搜到。
- **`date` 只精确到天**（统一记成北京时间零点），不能用来判断几点发的。偶尔还会出现明显错误的日期：实测见到过一条标成 2028 年的文章，还有一篇 7 月的美联社稿被标成 9 月 9 日。日期关键时要回原页面核对。做复盘测试时，`before:` 过滤也会受这个影响，漏进或漏掉个别条目。
- **`authority` 不可信。** 内容农场和直播吧都拿到 3 分。判断可信度要用 `sources.md` 的分级，不要用这个分数。
- **`need_content` 对虎扑特别有用。** 虎扑页面 Fetch 抓不到，但搜索索引里存着页面快照，包括回帖和"亮了"数。注意这是**索引时刻的快照**：亮了数通常偏低，也不能控制它什么时候刷新。
- 英文结果里聚合站和内容农场的比例明显高于中文结果。
- **查询条件不是严格过滤。** 带引号、带多个条件的查询，返回结果也可能不满足条件（盲测实测：同时带 Basketball Ground、LeBron、5、7 的查询返回了球鞋史文章），要逐条筛。
- **索引快照里的发帖时刻可能不可信**：实测见到过虎扑稿件的发帖时刻早于所写比赛的开赛时间。时间关键时回原页核对，核不了就记为未核实。
- **索引快照偶尔把两篇文章拼在一起**：网址和标题是一篇，正文后半截是另一篇（实测：76 人官网训练营公告的快照里拼进了媒体日实录）。拿快照当原文用之前，先核对网址、标题和正文是不是同一篇；对不上的部分不能当原文。

**索引里没有的站点**（`site:` 查询返回空）：reddit.com、x.com、twitter.com、instagram.com、threads.net。

## DeepSeek Fetch

`POST https://api.deepseek.com/v1/tools/fetch`，返回 Markdown 正文。

| 可以抓 | 抓不到 |
|---|---|
| 直播吧新闻页（含"热门评论"和顶/踩数） | 虎扑帖子页（超时） |
| Basketball-Reference | Reddit 全部地址（404） |
| Spotrac | X、Instagram、Threads、Nitter（404） |
| HoopsHype 传闻页、Hoops Rumors | Wikipedia（404） |
| 普通新闻站 | web.archive.org（404） |
| 搜狐号等中文自媒体页 | Yahoo Sports 文章页（404）：改用 Search 加 `need_content` 取索引快照 |
| | 脚本渲染的页面只拿到外壳：NBA.com 交易页、官方伤病报告索引页 |

Fetch 返回 404 的原因可能是地址无效、被目标站拦截、内容类型不支持，**不代表页面不存在**。

**返回成功也不代表内容完整。** 实测 Fetch 抓 NBA.com 比赛页返回 200，表格却丢了整列球员姓名，另一页只有一千多字的导航。拿到内容先看关键字段在不在。单次 Fetch 可能要 20 到 50 秒，脚本没有进度提示。

## 社交媒体：先定位，再试一次直连

DeepSeek 的搜索和抓取都进不了 X 和 Instagram，但这只是这两个服务的限制，不等于原帖读不到。2026-10-20 第三批核查实测：

- **X 帖子**用普通网页请求（`urllib`、`curl`）常能拿到 200，原始 HTML 里有帖子正文、账号和结构化的发布时间。
- **Instagram** 页面正文是登录外壳，但 `og:title`、`og:description`、`description` 这些 meta 标签里常有账号名和完整配文——这算读到了配文（记 `access_method: raw_html`），但证明不了没播放的视频内容。
- 所以写 `l3_ok` 之前，"实际试过打不开"要包括一次普通网页请求；这只证明那一条帖子能直连，不能推广到所有帖子。

定位原帖还是要**通过媒体报道**：

- 中文：`詹姆斯 更新社媒 after:日期`、`詹姆斯 ins 晒`。虎扑流言板、直播吧会报道值得关注的帖子，标题里通常写"INS 晒""更新社媒""转发"。
- 英文：`LeBron James Instagram post after:日期`。Sportskeeda、SI 等会报道并嵌入原帖。
- 延迟大约一天，而且只覆盖媒体觉得值得报道的帖子。
- 媒体对帖子内容的转述本身也要核对：能看到嵌入的原帖截图或原文时以原帖为准，看不到时注明"据 XX 转述"。

## 计费与限速

- Search 和 Fetch 都按成功请求计费，每 1000 次 5 元；无结果、失败、超时不计费。
- 账号级 5 QPS，Search 和 Fetch 分开计；Fetch 对同一目标域名另有限速。
- 一次完整核查一般在十几次调用以内，成本在一毛钱上下。

## 检索技巧

- **中文溯源**：用中文稿里的独特细节（具体数字、引语里的关键词）配 `site:bbs.hupu.com` 或 `site:zhibo8.com` 找到最早的中文稿，看文末"来源"。
- **英文溯源**：把中文引语里最独特的几个词回译成英文，加上 `"LeBron"` 和时间范围搜。找到聚合站文章后，顺着里面嵌的推文或 "per XX" 找首发。
- **找反证**：在关键词后加 `denies`、`refutes`、`false`、`not true`、`辟谣`、`否认`，专门搜一遍相反方向的报道。
- **时间线**：同一个关键词按 `after:` / `before:` 分段搜，确认每个说法最早出现的日期。
