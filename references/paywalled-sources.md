# 付费墙信源取证

NBA 的爆料和深度报道有相当一部分在付费墙后：The Athletic（Marchand、Amick、Buha、Slater 曾在此）、ESPN+ 的独家、纽约时报体育版。核查时常常只能读到别家的转述——2026-10-17 核 ESPN 纪录片那条，我们读的其实一直是 NBC Sports 对 The Athletic 的转述。

原则：**不绕墙**，但把能公开拿到的信息榨干，并且写清楚每个细节是从哪一级拿到的。

## 三条纪律

1. **不绕墙。** 不用绕过付费墙的服务、全文镜像、非授权转存。
2. **转述不等于原文。** 看不到原文时，转述只说明"据说原文这么写"，要有独立来源佐证才能写进结论。
3. **写明取证层级。** 状态块里每条证据的 `access` 字段写清楚是哪一级，否则读者会以为你读过全文。

## 取证阶梯

| 级别 | 是什么 | 能不能当证据 |
|---|---|---|
| `full` | 公开全文（没有付费墙，或者是官方公告） | 能 |
| `L1` | 公开元数据：标题、作者、发布时间、URL、导语 | 能，只限这些字段本身 |
| `L2` | 墙外可见的正文段落（多数付费墙放出前两三段，核心事实常在里面） | 能 |
| `L3` | 别家的转载、转述、摘要 | 只是线索：要判断是否同源，并找 L4 佐证 |
| `L4` | 独立来源：官方记录、通讯社自己的采访、当事人公开表态 | 能 |

**状态块里怎么记**：每条证据的 `access` 写的是"这条证据所支撑的内容，我们是在哪一级读到的"，取值 `full`、`L1`、`L2`、`L3`：

- 读的是原文本身而且能读全（官方记录、公开文章）→ `full`；原站对普通请求直接返回了全文（没有登录、没有换接口或镜像绕墙），即使页面源码里带付费墙标记，也记 `full`，`access_method` 记实际方式（`live` / `raw_html`），在 note 里写明带有付费墙标记；
- 原文在墙后，只读到元数据或公开段落 → `L1` / `L2`；
- 读的是别家对原文的转述（例如 NBC Sports 转述 The Athletic）→ `L3`；
- 公开场合（媒体日、发布会、赛后采访）在场记者的署名报道、通讯社现场稿，以及写明"在给本报的声明中"的声明 → `full`，它们不是转述；判法见 SKILL.md 的"在场记者的报道不是转述"；
- 别家网站**完整刊载了原记者的署名原稿**（例如 6abc 刊载 ESPN 记者 McMenamin 署名、带 ESPN 版权的文章）→ `full`，但仍按原记者算，不算一个新的独立来源。只刊了摘要或改写的，按转述记 `L3`。

L4 不是单条证据的属性，而是"另有一条独立证据"——它本身按 `full` 记。某个核查点判为"准确"、引用的证据却全是 `L3` 时，检查脚本会报错；确属拿不到原文的社媒帖子，按 SKILL.md 的 L3 规则在该核查点写结构化的 `l3_ok`，脚本核对结构后降为提醒。

`access` 记的是取证层级，另一个可选字段 `access_method` 记取得方式（live / raw_html / index_snapshot / relay）：同样是 `full`，读的是实时页面还是搜索索引的快照，可信程度不一样。

## 怎么做

**第一步：拿 L1 元数据。** 这一步成本最低、价值最高。

- 网页源码里的 JSON-LD（`<script type="application/ld+json">`，`@type: NewsArticle`）通常有 `headline`、`datePublished`、`author`，**比页面上显示的时间更准**，适合用来排时间线、判断谁先报的。
- `og:title`、`article:published_time` 这类 meta 标签也能用。
- URL 里的 slug 常常就是原标题的压缩版，可以用来看转载有没有改标题。
- 抓不到网页源码时（DeepSeek Fetch 只返回 Markdown），用搜索结果里的标题、日期和摘要，注意 `date` 只精确到天。

**第二步：读 L2 公开段落。** NBA 报道的核心事实（谁、签多少、几年、什么选项）多半就在导语和第一段里。

**第三步：判断 L3 转述是不是同源。**

| 看到的情况 | 结论 |
|---|---|
| 写着 "per The Athletic""according to Shams"，或"据 XX 报道" | 同源，不独立 |
| 和原文公开段落逐字一致 | 同源，不独立 |
| 通讯社（AP、路透）或别家记者自己采访到的 | 独立 |
| 官方公告、官方交易记录 | 独立，而且是最高级 |
| 没署名的聚合站、AI 摘要站 | 只是线索 |

**第四步：找 L4 佐证**墙后的关键细节：官方交易记录、球队公告、当事人或经纪人的公开表态、通讯社。

## 转载漂移清单

转述每经过一手，就可能变一点。逐项核对，命中就降级：

- **日期漂移**：时区换算错（美国晚上 = 北京次日），或者聚合站的日期本身就错（实测见过 7 月的美联社稿被标成 9 月）。
- **作者漂移**：转载不带署名，传两手就成了"据报道""美媒称"。
- **数字漂移**：区间被压成一个数、币种或单位被改（"388 万"是美元，不是人民币）、"最多 X"被写成"X"。
- **措辞升级**："接近达成"变成"即将官宣"，"有兴趣"变成"想要"。这是最常见的走样。
- **细节无源**：转述里出现原文公开部分不可能有的细节（具体人名、数字、日期），没有独立来源时：转述说不出这些细节从哪来，按查无出处；转述点明了来源（"据 ESPN 报道"）、只是原文读不到，按无法证实。

## 判定规则

| 情况 | 处理 |
|---|---|
| L1、L2 足以支撑这个核查点 | 可以判定，注明取证层级 |
| 细节来自 L3，并有 L4 独立佐证 | 可以判定，说明"细节取自对该报道的转述，并经 XX 佐证" |
| 细节只来自 L3，没有 L4 | **无法证实**。唯一例外见 SKILL.md 的 L3 规则：工具够不着的社媒原帖、有可靠媒体逐字收录时，写 `l3_ok` |
| 几个 L3 之间说法矛盾 | 写"说法不一"，列出各版本和出处，不取平均、不拼成一个区间 |
| 原文本身是"援引匿名知情人士" | 结论里注明信源性质。匿名信源不能当一手证实，哪怕它出自大报 |

## 写法

> The Athletic 原文在付费墙后。本核查依据其公开的标题、发布时间与导语段（L1/L2）；"接近达成"一说另由 NBC Sports、NY Post 的转述（L3，同源于 The Athletic）佐证，独立来源（L4）方面目前没有 ESPN 或本人的公告。

不要这样写：

- "据报道"——不说是哪家、哪篇、哪天；
- 把 L3 转述写成"本次核查读到原文"；
- 用聚合站的日期覆盖原文的发布时间。
